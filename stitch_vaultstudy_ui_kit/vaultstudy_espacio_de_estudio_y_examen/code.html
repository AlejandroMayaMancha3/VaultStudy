Módulo: Álgebra Relacional, Optimización de Índices y Agregaciones

PREGUNTA 3.1 [VALOR: 2.5 PTOS] ID: SQL-REL-2024-Q3

Realizar una consulta analítica que devuelva todos los estudiantes matriculados en más de dos asignaturas dentro del semestre lectivo 'SEMESTRE_B', asegurando que sólo se contabilicen expedientes con estatus de matrícula activo.

edit_note Punto Clave Resaltado por el Estudiante

"Para filtrar agregaciones por umbral de cardinalidad se debe emplear rigurosamente la cláusula GROUP BY con condición HAVING count(*) > 2, garantizando que el WHERE previo descarte matrículas anuladas o suspendidas."

Esquema Relacional Involucrado:

TABLA CLAVE PRIMARIA CLAVE FORÁNEA CAMPOS RELEVANTES
estudiantes id_estudiante - nombre, email, fecha_alta
matriculas id_matricula id_estudiante, id_asig semestre, estado, calificacion
asignaturas id_asig - creditos, nombre_asig, depto

[Restricción] La ordenación final debe ser estrictamente descendente según el número total de asignaturas activas computadas.

[Optimización] Comprobar el plan de ejecución y evitar escaneo secuencial (Seq Scan) en la tabla matriculas mediante índice compuesto.

Para combinar tablas relacionadas garantizando la integridad de datos utilizamos JOINS. En exámenes prácticos recordar que el INNER JOIN excluye valores nulos y registros que no satisfacen la igualdad formal de claves foráneas.

Al calcular agregados agrupados por múltiples entidades (como estudiante y nombre), toda columna en el SELECT que no esté contenida dentro de una función de agregación (COUNT, SUM, AVG) debe declararse expresamente en el GROUP BY.

sql queries/relacionales.sql
1 2 3 4 5 6 7 
SELECT e.id_estudiante, e.nombre, COUNT(m.id_asignatura) AS total_asignaturas
FROM estudiantes e
INNER JOIN matriculas m ON e.id_estudiante = m.id_estudiante
WHERE m.estado = 'ACTIVO'
GROUP BY e.id_estudiante, e.nombre
HAVING COUNT(m.id_asignatura) >= 2
ORDER BY total_asignaturas DESC;

TIP DE EXAMEN // SQL ENGINE Prioridad Alta

Utilizar siempre alias claros (e para estudiantes, m para matriculas) para evitar ambigüedades en columnas compartidas. Si la prueba penaliza la sintaxis estándar SQL92, evita el uso de comas implícitas en el FROM.
